Overall Status
For the implementation of insert() and _insert(), there were limited uses of AI outside of
Google’s search engine. The provided project PDF was a substantial resource in constructing
these methods and served as the primary reference for the major components. The start of
insert() validates that the key is an IntegerKey and rejects anything else with a
KeyNotMatchException. The major components handle an empty tree and root split in insert():
Empty tree: if headerPage is INVALID_PAGE, a new leaf page is made and assigned as root.
Root split: using _insert(), if it returns a non-null KeyDataEntry, the root will split. This
creates a new index page with the old root as the left child and one key entry as the new
sibling, and the tree grows here.
_insert() is a recursive top-down doubly-linked algorithm that pins pages, index entries, and
leaf entries:
Index: the page locates the child to recurse into and returns if the child does not split. If the
child splits, the page either takes the new entry or splits itself so it is not duplicated across
levels.
Leaf: the page inserts the new record if there is space. If full, it allocates a new linked
sibling to balance the records and copies the smallest key upward so the data remains intact at
the leaf level.

For the implementation of NaiveDelete() for the overall B+ tree behavior.
This portion of the implementation locates the proper leaf page, searches the correct key
range, identifies the exact <key, rid> pair to remove, and deletes it without redistribution or
merging. This follows the project specification for a naive delete and keeps the delete
behavior consistent with the rest of the B+ tree logic.

Logical Errors

In insert() the start of the method is to validate integer key, what was initially added was
headerPage.get_keyType() != AttrType.attrInteger) in the if-condition. This was not type safe as
it interprets string as string bytes and uses them into pages. The solution was to use (!(key
instanceof IntegerKey), rejecting strings and checks object’s runtime type.

In delete() the method is to delete by key value alone rather than the full <key, rid> pair. In a
B+ tree that allows duplicates, a delete routine may incorrectly remove the first matching key
value without verifying whether the specific record is the exact one required, which can lead to
deleting the wrong entry whenever multiple records share the same key. The solution was to
compare both the key and the RID, and remove only the exact <key, rid> pair using
if (candidateRid.equals(rid)).

In _insert() the method is to handle traversal and split propagation after a child page split. If
the separator key produced by a split is not propagated upward correctly, the parent page may
route future lookups to the wrong child or reorder entries incorrectly, which can cause a tree
to become inconsistent after several insertions. The solution was to propagate the promoted
key and child page pointer consistently using BT.keyCompare(upEntry.key, tmpEntry.key) > 0
and ensure that the parent chooses the correct traversal path based on the compare result.
